# dsh-auto-memory — agent notes

File-based persistent project memory for DeepSeek Harness (DSH). This repo is a DSH **bundle plugin**: a profile selects `@y0shua1ee/dsh-auto-memory` in `dsh.profile.bundles`, the package's `cordis.patch.yml` mounts the row, and framework packages stay peers.

## Layout

| Path | Role |
|---|---|
| `src/index.ts` | plugin entry: `name`, `inject`, `Config`, `apply`; registers tool, prompt section, pre-step listener |
| `src/config.ts` | Schemastery `Config`, direct-apply normalization, `$DSH_HOME` root resolution |
| `src/paths.ts` | DSH-compatible `projectKey`, `.git` root discovery (linked worktrees share the main checkout), path display |
| `src/store.ts` | virtual `/memories` filesystem, atomic writes, limits, symlink/traversal guards, index maintenance and read-budget checks |
| `src/memory-frontmatter.ts` | memory-file frontmatter parser (`name`, `description`, `metadata.type`, `modified`), stable issue codes, non-blocking checks, write-time timestamp |
| `src/render.ts` | bounded `MEMORY.md` snapshot, escaping, SHA-256 digest |
| `src/guidance.ts` | system-prompt guidance |
| `src/tool.ts` | `memory` tool options (no `defineTool` import, so command semantics are testable) |
| `src/rule-frontmatter.ts` | `paths:` frontmatter parser |
| `src/rule-glob.ts` | `*` / `**` / `?` / brace / class glob matcher |
| `src/rules.ts` | rule discovery, caching, budgets, rendering (pure; no DSH imports) |
| `src/rules-inject.ts` | `agent/pre-step` rule injection and `tools/result` file-touch tracking |
| `src/types.ts` | shared structural types for the DSH boundary |
| `types/` | ambient declarations for the four peer packages used at build time |
| `lib/` | compiled ESM + `.d.ts`; generated by `pnpm build`, never edit by hand |
| `cordis.patch.yml` | bundle patch that mounts the `dsh-auto-memory` row |
| `assets/icon.svg` | Plugins-page icon |
| `test/` | pure tests plus a loader-based integration test |

## Commands

Use Node 22 or newer and pnpm. The packaged desktop app ships its own Node and pnpm under its runtime directory if the shell has none. Edit `src/`, then rebuild; `lib/` is generated and committed so a `link:` profile loads it without a build step.

```bash
pnpm install
pnpm build
pnpm test              # build, then every test; integration skips without a runtime

# pure logic only
node --test test/store.test.mjs test/memory-frontmatter.test.mjs test/render-paths.test.mjs test/rules.test.mjs test/index-budget.test.mjs test/modified.test.mjs

# extract the packaged runtime once (writes /tmp/dsh-app by default)
node scripts/extract-runtime.mjs

# plugin wiring, injection, tool execution, rules
DSH_APP_NODE_MODULES=/tmp/dsh-app/dsh/node_modules \
  node --import ./test/register.mjs --test test/plugin.test.mjs test/rules-plugin.test.mjs test/worktree-plugin.test.mjs
```

The integration loader maps `@deepseek-ai/*` to the packaged app when a runtime is present; the build uses `types/*.d.ts` shims so it never depends on the runtime being installed.

## DSH interfaces used (tested on 0.2.1-rc.3 through 0.2.1-rc.5)

- `ctx.tools.register(defineTool({...}))` — `@deepseek-ai/dsh-tools`
- `ctx.systemPrompt.section({name, order, text})`, `getSectionOrder("TOOL_GOAL")`
- `ctx.on("agent/pre-step", async (payload, next) => ...)`, returning a replacement `{kind: "enter", messages}`
- `ctx.workingDirectory.ensure(agent, signal)`
- `agent.inbox.prepend/replace/remove`, `agent.session.surface.nodes`, `agent.session.eventAt(seq)`
- `ctx.on("tools/result", (exec, result) => ...)` for `read` / `write` / `edit` file touches
- `createUserMessage`, `HarnessError` — `@deepseek-ai/dsh-llm`

## Invariants

- Memory lives **outside** the workspace, under the configured `$DSH_HOME` root; all paths are resolved and confined to it.
- Never follow symlinks inside the memory root; reject traversal, hidden segments, non-`.md` files, and binary content.
- Writes are same-directory temp + `rename`, mode `0600`; mutations serialize per project store.
- Injection is a user-role `<system-reminder>` with a rendered-snapshot digest in `source`; never inject twice for one digest, and re-inject after compaction when the digest is no longer on the surface.
- `MEMORY.md` is the only automatically injected file; topic files are read on demand through the tool.
- The injectable index budget is 200 lines / 25KB (configurable): the store warns near it and, after a write leaves the index over it, returns `MEMORY_INDEX_OVER_LIMIT` so the model rewrites the index. The on-disk index is read up to a 4MiB safety cap; only its start is injected when larger.
- Topic files written through `memory` get an ISO 8601 `metadata.modified` timestamp when they have frontmatter; `MEMORY.md` is not stamped.
- Linked git worktrees share the main checkout's project root (and memory directory); project rules stay anchored to the worktree root; submodules remain separate.
- Subagents get the tool but not the injection by default (`injectInSubagents`).
- Rules: user roots are trusted and may be symlinks (Nix/Home Manager); project roots are repository input, and symlinks resolving outside the project are skipped. Rule bodies are escaped and framed as context.
- Rules with `paths` stay out of context until `read` / `write` / `edit` touches a match; unconditional rules inject at the first step.

## Gotchas

- `maxFiles` counts `MEMORY.md` too.
- `create` auto-creates `MEMORY.md` when a topic file is the first memory.
- `maxIndexLines` / `maxIndexBytes` are read budgets, not write limits: a write that leaves the index over budget lands on disk and then throws `MEMORY_INDEX_OVER_LIMIT` (near the limit, the tool output warns instead). `maxFileBytes` no longer caps `MEMORY.md`; the 4MiB safety cap does.
- `modified` is updated on `create`, `str_replace` and `insert` for topic files with frontmatter; `rename` preserves it. The parser accepts both `metadata.modified` and a top-level `modified`.
- Rule globs follow the Claude Code table: a bare pattern such as `*.md` matches at any depth, `/*.md` is root-only, `src/*.ts` is anchored, `\[` is a literal `[`, and an unreadable `[` matches nothing. A malformed inline `paths:` list falls back to an unconditional rule.
- Rule discovery is capped at 8 directory levels below each rule root; a subdirectory's own `.claude/rules` directory is not discovered.
- Memory files follow Claude Code's format (one fact per file, `name` / `description` / `metadata.type` frontmatter, `[[name]]` → `/memories/<name>.md`). Frontmatter is advisory: no command refuses a file for it. `create` lists every problem; `str_replace` / `insert` / `rename` list only problem codes they introduced, so changing one invalid value to another does not re-report it. An invalid `name` never becomes an index title; the file name is used instead, and v0.3.0 titles with an invalid name are recognized as legacy generated values and normalized on the next edit or rename while the content still carries that invalid name. A valid `name` must match the file stem; a file under a subdirectory also warns because `[[name]]` resolves to `/memories/<name>.md` at the root. New index lines take `name` and `description`, falling back to the file name and first body line. `str_replace` / `insert` on a topic file refresh its index line's title and hook only where they still equal the old generated values; hand-written parts are kept. Index maintenance parses the leading `[title](target)` link with bracket matching and exact targets; whitespace targets are written as `<...>`; task lists are ignored; CRLF is preserved by create/edit/delete/rename.
- `str_replace` requires exactly one occurrence; `insert` is 0-based and clamps to the line count.
- Rules are re-discovered every pre-step with an mtime/size cache; a changed rule re-injects with a new digest.
- The desktop app's `$DSH_HOME/profiles/desktop` installs `@y0shua1ee/dsh-auto-memory` from npm, so repo changes reach it only after a publish and an update of that profile; **code changes need an app restart**, config changes can hot-reload.
- The bundle patch entry id is `dsh-auto-memory`; the package/row name is `@y0shua1ee/dsh-auto-memory`. Profile overrides address the id `dsh-auto-memory`, not the old row id `auto-memory`.
